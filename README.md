# SweetPlanet · 甜甜星球

一款可以在桌面浏览器中游玩的 3D 甜品冒险游戏。操控椰蓉香草蛋糕兔，跳过蛋糕平台，探索糖果浮岛，再穿越巧克力峡谷，飞向云朵终点。

**[在线试玩](https://sweet-planet-d0g79b22qfe6a476a-1534142512.tcloudbaseapp.com/)** · 桌面键鼠操作 · 两个可游玩关卡

![第一关：糖果森林](docs/images/level01.png)

## 游戏内容

**第一关 · 糖果森林**

从蛋糕跳台出发，借助棉花糖弹台探索高处，穿过果冻花园和旋转糖杖，再沿 S 形彩虹滑道冲坡飞跃。沿路收集至少 **35 个甜品**，抵达彩虹门平台并停稳，即可成功通关。收集 35 / 55 / 75 个，分别获得铜星、银星、金星。

**第二关 · 巧克力工厂峡谷**

跨过崩塌的巧克力道路，避开滚球闸门，穿越传送带和喷泉，乘缆车抵达休息台。腾空后按住 Shift 展开滑翔，沿彩虹航线飞向云朵终点。落到终点台即可通关；收集全关甜品的 40% / 70% / 90%，分别获得铜星、银星、金星。

![第二关：巧克力工厂峡谷](docs/images/level02.png)

两关各有 **3 格生命**。受伤或坠落会扣除生命；坠落后回到最近的安全平台，保留收集和计时。生命耗尽后，需要重新挑战本关。

## 操作

| 动作 | 按键 |
| --- | --- |
| 移动 | W / A / S / D |
| 跳跃 / 空中二段跳 | Space |
| 旋转视角 | 鼠标右键拖动 |
| 缩放视角 | 鼠标滚轮 |
| 暂停 / 继续 | Esc |
| 第一关滑道换线 | A / D |
| 第二关展开滑翔 | 离开休息台边缘并腾空后，按住 Shift |

第一关滑道会自动前进，滑道中不能跳跃。第二关滑翔沿预设曲线自动巡航。

## 本地运行

需要 **Node.js 24 或更新版本**，推荐使用 Chrome 或 Edge，并开启浏览器硬件加速。

下载或克隆仓库后，在项目根目录执行：

```bash
npm start
```

打开 **http://127.0.0.1:5189/**，即可进入第一关。第二关也可以直接访问 http://127.0.0.1:5189/level02.html 。

Windows 用户可以双击 **启动SweetPlanet.cmd**。运行期间保持服务窗口打开；不要直接双击 HTML 文件。

项目不需要执行 `npm install`，也不需要构建。Three.js、模型和运行组件均随仓库提供，游戏运行不依赖远程 CDN 或在线账号服务。

如果端口已被占用，可指定其他端口启动，例如：

```powershell
# Windows PowerShell
$env:PORT = '5190'
npm start
```

```bash
# macOS / Linux
PORT=5190 npm start
```

然后访问 http://127.0.0.1:5190/ 。

## 场景编辑

启动本地服务后，打开 http://127.0.0.1:5189/scene-editor.html ，可以调整第一关的装饰、踏板位置和尺寸。Windows 用户也可以双击 **打开场景编辑器.cmd**。

布局保存在当前浏览器、当前网址的本地存储中。编辑完成后可以导出 JSON 备份；换浏览器、域名或端口时，需要重新导入。

## 技术与资源

- **JavaScript ES Modules、HTML、CSS**：游戏逻辑与界面。
- **Three.js 0.160.1 / WebGL**：3D 场景、模型加载、灯光与渲染。
- **Lux3D**：甜品主题模型制作与处理。
- **meshoptimizer**：模型简化和场景渲染优化。
- **Web Audio API**：音乐与音效合成。
- **Node.js 内置 HTTP 服务**：本地运行。

游戏使用自定义角色移动、平台碰撞和机关系统；模型以 GLB 格式提供。场景编辑器、资产图鉴及本地检查工具也保留在仓库中。

## 开发检查

```bash
npm test
```

运行移动、碰撞、关卡规则、机关、编辑器和资源完整性测试。

```bash
npm run test:routes
```

通过固定步长模拟检查第一关路线，并将结果写入本地 `artifacts/level01/`。这项检查不包含浏览器画面验收。

## 部署

游戏可以部署到静态网站托管服务，不需要后端或数据库。将仓库内的 HTML、`src/`、`assets/` 和 `scripts/` 放到网站根目录，保留目录结构即可。

资源地址使用 `/assets/`、`/src/` 等根路径。使用 GitHub Pages 的 `用户名.github.io/仓库名/` 项目子路径时，需要先适配这些路径；当前源码可以直接部署到域名根目录。
